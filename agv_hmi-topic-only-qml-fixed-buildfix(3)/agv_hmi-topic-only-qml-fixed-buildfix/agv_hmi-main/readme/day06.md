터미널 **3개**를 각각 열어서 아래 순서대로 실행해 주세요.

### 1단계: C++ ROS2 백엔드 서버 (터미널 1)

> 웹 서버가 상태를 조회할 기준 백엔드(8080 포트)를 먼저 실행합니다.

```bash
cd ~/ros2_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 run agv_hmi_server agv_hmi_server

```

* **확인**: `NetworkServer listening on port: 8080` 로그 출력

### 2단계: Blazor Web HMI 서버 (터미널 2)

> C++ 백엔드(8080)와 연결을 맺으며 웹 화면(8000 포트)을 띄웁니다.

```bash
cd ~/GuideRobot_WebHmi/GuideRobot.WebHmi-ubuntu-net10-final
RobotServer__BaseUrl=http://127.0.0.1:8080/ dotnet GuideRobot.WebHmi.dll --urls http://127.0.0.1:8000

```

* **확인**: `Now listening on: [http://127.0.0.1:8000](http://127.0.0.1:8000)` 로그 출력

### 3단계: Cloudflare 터널 실행 (터미널 3)

> 완성된 웹 서버(8000)를 외부 인터넷 주소로 연결해 줍니다.

```bash
cloudflared tunnel --protocol http2 --url http://localhost:8000

```

* **확인**: `https://[랜덤문자열].trycloudflare.com` 형태의 새 주소 확인 후 접속

아니요, **Qt 팀과 UI(웹 HMI) 팀에 각각 다른 주소를 전달해 주셔야 합니다.**

만드는 시스템 구조상 두 개의 서로 다른 프로그램(서버)이 각각 다른 포트에서 돌고 있기 때문입니다.

---

### 1. QT 팀 (로봇 내장 화면 / C++ 백엔드)

* **연결 대상:** C++ 백엔드 서버 (`agv_hmi_server`, **8080번 포트**)
* **주소 형태:** `https://[현재-터널주소]/api/status` 또는 `/api/command`
* **설명:** 브라우저로 접속했을 때 `{"error": "Not Found"}`가 뜨던 그 주소가 바로 C++ 서버용 주소입니다. Qt 팀은 이 주소로 REST API(`GET /api/status`, `POST /api/command`)를 호출해야 합니다.

### 2. UI / 웹 HMI 팀 (Blazor 웹 화면)

* **연결 대상:** 웹 HMI 서버 (`GuideRobot.WebHmi`, **8000번 포트**)
* **주소 형태:** 순수한 `https://[랜덤문자열].trycloudflare.com` (뒤에 경로 없음)
* **설명:** 브라우저로 접속했을 때 로봇 제어 웹 UI 화면(대시보드)이 통째로 뜨는 주소입니다.

### 요약

* **Qt 팀용:** 8080번 포트로 연결된 클라우드플레어 터널 주소 (`/api/...` 경로 사용)
* **UI(웹) 팀용:** 8000번 포트로 연결된 클라우드플레어 터널 주소 (웹 화면 전체)

따라서 **두 팀의 역할이 다르다면 각각 맞는 포트의 터널 주소를 따로 파서 전달**해 주셔야 합니다!

**아닙니다! 하나를 꺼야 할 필요 없이, 터미널 창을 각각 다른 개별 창(또는 탭)으로 띄워둔 상태라면 둘 다 동시에 켜두셔도 아무 문제 없습니다.**

### 이유

* 터미널 창 하나당 **하나의 클라우드플레어 터널 프로세스**가 실행됩니다.
* 8080번 터널 창과 8000번 터널 창을 각각 다른 터미널에서 실행했다면, 각각 독립된 서로 다른 외부 주소를 부여받아 동시에 작동하게 됩니다.

### 올바른 운영 방법

1. **터미널 1번 (C++ 백엔드용 - 8080번)**
* 실행 명령어: `cloudflared tunnel --protocol http2 --url http://localhost:8080`
* **용도**: Qt 팀에 전달할 API 주소 생성용 (이 창을 끄면 안 됨)


2. **터미널 2번 (웹 HMI 화면용 - 8000번)** *(만약 웹 UI도 외부 공유가 필요하다면)*
* 새 터미널 창을 열고: `cloudflared tunnel --protocol http2 --url http://localhost:8000`
* **용도**: UI 팀에 전달할 웹 화면 주소 생성용 (이 창도 끄면 안 됨)



따라서 두 팀 모두에게 외부 접속 주소를 제공해야 한다면, **터미널 창을 2개 띄워 각각 다른 포트(`8080`, `8000`)로 터널을 실행한 채로 두 개 다 유지**하시면 됩니다!

Qt 팀은 웹 브라우저로 접속해서 보는 **예쁜 '웹 화면(UI)'을 받는 것이 아닙니다.**

Qt 팀은 자체적인 Qt 프로그램을 개발하고 있기 때문에, 화면을 받는 게 아니라 로봇 서버와 통신할 수 있는 'API 주소'와 '데이터(JSON) 규격'을 전달받아야 합니다.

---

### 🖥️ Qt 팀이 실제로 보거나 다루게 되는 것

1. **브라우저에서 확인하는 데이터 (API 응답 결과)**
* Qt 팀이 `https://[주소]/api/status`에 접속했을 때 보게 되는 것은 웹페이지가 아니라 다음과 같은 **텍스트(JSON) 데이터**입니다.
```json
{
  "status": "idle",
  "battery": 85,
  "location": "room_301"
}

```


* 이 데이터를 Qt 프로그램 내부로 가져와서 화면에 글자나 그래프로 띄우는 것입니다.


2. **Qt 프로그램 내부의 기능 (버튼 및 제어)**
* Qt 팀은 프로그램 안에 **[목적지 이동]** 버튼이나 **[취소]** 버튼을 만들고, 버튼을 누를 때 서버로 아래와 같은 신호(POST 요청)를 보내도록 코드를 작성하게 됩니다.
* 이동 요청: `{"destination": "room_301"}`
* 취소 요청: `{"command": "cancel"}`

* **Qt 팀**: 웹 화면이 뜨는 게 아니라, 자기들이 만들고 있는 **Qt 프로그램에 서버 주소를 연동해서 데이터를 주고받는 통로**를 연결하는 것입니다. (8080번 포트)

따라서 Qt 팀에게는 "웹 화면이 안 뜨고 이상한 글자(`Not Found` 또는 JSON 데이터)가 뜨는 게 정상이니, 이 **API 주소**를 써서 통신 프로그램을 개발해달라"고 전달하시면 됩니다!
