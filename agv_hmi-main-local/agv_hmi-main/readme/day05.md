## 키는 순서 

**C++ 백엔드 서버(`agv_hmi_server`)를 먼저 켜고, 그 다음에 Cloudflare 터널을 키는 것이 정석입니다.**

물론 순서가 바뀐다고 해서 무조건 터져버리는 건 아니지만, 구동 순서에 따른 명확한 이유가 있습니다.

---

### 1. 왜 `agv_hmi_server`를 먼저 켜야 할까요?

* **8080 포트의 주인은 C++ 서버입니다:** Cloudflare 터널은 로컬의 8080 포트에서 실행 중인 웹 서버를 외부 인터넷과 연결해 주는 **'통로(다리)'** 역할을 할 뿐입니다.
* **접속 대상의 존재 여부:** 다리를 놓으려면 도착지(C++ 서버)가 먼저 존재해야 합니다. C++ 서버가 꺼진 상태에서 Cloudflare를 먼저 켜면, 외부 요청이 들어왔을 때 Cloudflare가 연결할 대상을 찾지 못해 `502 Bad Gateway` 에러를 뱉게 됩니다.

---

### 💡 올바른 서버 구동 순서 (추천 워크플로우)

#### 1단계: ROS2 환경 설정 및 C++ 백엔드 서버 실행

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash  # 본인 워크스페이스 경로
ros2 run agv_hmi_server agv_hmi_server

```

*(터미널에 `Listening on Port 8080...` 로그가 뜨는 것을 확인합니다.)*

#### 2단계: Cloudflare 터널 실행 (새 터미널)

```bash
cloudflared tunnel --url http://localhost:8080

```

*(터미널에 생성된 `[https://xxxx.trycloudflare.com](https://xxxx.trycloudflare.com)` URL을 복사하여 웹 UI나 API 요청에 사용합니다.)*

# 📂 2. 파일 및 프로그램 역할 정리

### ① `agv_hmi_server` (C++ 백엔드 / 중계 서버)

* **역할:** **웹(UI)과 로봇(ROS2)을 이어주는 '통역사'**
* **동작:**
1. 외부 웹 UI에서 보낸 HTTP POST 요청(`POST /api/command`)을 받음.
2. 요청에 들어있는 JSON 데이터에서 `"destination": "room_302"` 문자열을 정제하고 추출.
3. 추출한 목적지를 ROS2 시스템에서 사용할 수 있는 형식으로 변환하여 전달.



### ② `agv_nav2_manager` (ROS2 자율주행 관리 노드)

* **역할:** **AGV 이동 및 위치 관리를 담당하는 '자율주행 총괄자'**
* **동작:**
1. AGV의 초기 위치(`📍 초기 위치 설정 완료 (-2.0, -0.5)`)를 설정하고 상태를 모니터링함.
2. `agv_hmi_server`나 로직으로부터 목표 지점을 전달받으면, ROS2 Nav2 Action Client를 호출하여 AGV를 이동시킴.



### ③ Nginx & Cloudflare Tunnel (`cloudflared`)

* **역할:** **스마트폰/외부 디바이스 ↔ 내 우분투 서버를 연결하는 '통신 도로'**
* **동작:** Cloudflare가 고유 HTTPS URL을 만들면, Nginx를 거쳐 내 PC의 C++ 서버 80번 포트로 안전하게 들어오게 만듦.

# 🤝 3. 팀원들과의 역할 분담 (누가 무엇을 주는가?)

현재 전체 시스템은 **[UI팀 (웹)] / [Qt팀 (실물 모니터 GUI)] / [나 (백엔드 및 ROS2 통합)]** 3단계 구조로 일하고 계십니다.

```
┌─────────────────┐       HTTP / API       ┌─────────────────────────┐
│   UI팀 (Web)    │ ────────────────────> │                         │
└─────────────────┘                        │                         │
                                           │    현빈 님 (백엔드/ROS2)  │ <───> [Nav2 자율주행]
┌─────────────────┐    ROS2 Topic/Service  │  (agv_hmi_server 등)    │
│  Qt팀 (Onboard) │ <────────────────────> │                         │
└─────────────────┘                        └─────────────────────────┘

```

### 1) 🎨 UI팀 (Web HMI)에서 받는 것

* **전달물:** 스마트폰, 태블릿, PC 브라우저에서 볼 수 있는 **웹 화면(HTML/CSS/JS)**.
* **보내주는 데이터:** 사용자가 웹 화면에서 버튼을 누르면, **HTTP POST 방식**으로 서버에 JSON 데이터를 쏩니다.
* **예시:** `POST /api/command` ➡️ `{"destination": "room_302"}`


* **현빈 님의 역할:** UI팀이 보낸 이 JSON 데이터를 에러 없이 깔끔하게 받아내어 문자열(`room_302`)을 꺼내는 것 (방금 성공하신 부분!).

### 2) 🖥️ Qt팀 (Onboard GUI)에서 받는 것

* **전달물:** AGV 로봇 몸체에 실제로 달려있는 터치모니터(C++/Qt)용 프로그램.
* **보내주는 데이터:** 로봇 현장에서 작업자가 직접 화면을 터치했을 때 발생시키는 **ROS2 Topic / Service 메시지**.
* **예시:** 로봇 실물 화면에서 [비상정지], [수동 조작], [302호 이동] 버튼을 누르면 ROS2 메시지가 직접 발행됨.


* **현빈 님의 역할:** Qt팀 프로그램과 ROS2 노드 간 통신이 원활하게 이루어지도록 Topic/Service 인터페이스를 맞추고 상태를 공유하는 것.

# 🔄 4. 전체 동작 데이터 흐름 (예: 302호 이동 요청 시)

실제 서비스가 동작할 때 일어나는 전체 과정입니다.

```text
1. [사용자] 
   스마트폰에서 Cloudflare 링크(https://xxx.trycloudflare.com)로 접속 후 '302호 이동' 버튼 클릭

2. [UI팀 웹 화면] 
   서버로 HTTP POST 요청 전송: {"destination": "room_302"}

3. [Cloudflare & Nginx] 
   보안 위험 없이 우분투 80번 포트(agv_hmi_server)로 전달

4. [현빈 님의 C++ agv_hmi_server] (현재 위치!)
   - Incoming Request 확인 및 Raw Body 파싱
   - Cleaned Body: {"destination": "room_302"} 정제 성공
   - "room_302" ↔ 사전 정의된 좌표 (x: 3.5, y: -1.2, yaw: 1.57) 매핑

5. [agv_nav2_manager & Nav2]
   - 매핑된 좌표를 Nav2 Goal Pose로 전달
   - AGV 바퀴 모터가 구동되며 302호로 자율주행 시작

```

### 🌐 1. 웹 통신 및 API 처리 (UI팀 연동)

UI팀이 만든 웹 화면에서 보내는 명령을 가장 먼저 받아내는 문지기 역할입니다. 방금 로그에서 확인했던 `"room_302"` 파싱 작업이 여기서 일어납니다.

* **`networkserver.cpp` / `networkserver.h**`
* **역할:** Nginx를 거쳐 들어온 HTTP POST 요청(웹 UI의 명령)을 수신하고 분석하는 서버 클래스입니다.
* **현재 상태:** 들어온 JSON 데이터에서 `{"destination": "room_302"}`를 성공적으로 분리해내는 역할을 완벽히 수행하고 있습니다.



### 🤖 2. 자율주행 및 ROS2 제어 (Nav2 연동)

`networkserver`가 받아온 목적지 글자를 실제 로봇의 바퀴를 굴리는 주행 명령으로 바꿔주는 핵심 두뇌입니다.

* **`Nav2Manager.cpp` / `Nav2Manager.hpp**`
* **역할:** ROS2의 Navigation2(Nav2) 패키지와 통신하며 AGV의 주행을 제어합니다.
* **핵심 기능:** `"room_302"`라는 글자를 넘겨받으면, 이를 실제 지도 상의 X, Y 좌표로 변환하여 Nav2로 전송(`NavigateToPose` 액션 호출)하고, AGV가 잘 도착했는지 상태를 모니터링합니다.


* **`nav2_msgs/action/NavigateToPose`**
* **역할:** Nav2에게 "어디로 가라"고 명령할 때 사용하는 ROS2 표준 메시지/액션 형식 정의 파일입니다.



### 🖥️ 3. 로봇 본체 터치화면 (Qt팀 연동)

AGV 로봇 껍데기에 붙어있는 실제 모니터 화면을 구성하는 파일들입니다. Qt 프레임워크를 사용해 만들어졌습니다.

* **`hmi_design.qml`**
* **역할:** Qt/QML로 작성된 **GUI 화면 디자인 코드**입니다. 화면의 버튼 모양, 색상, 배치 등 UI 요소가 정의되어 있습니다.


* **`qml.qrc`**
* **역할:** QML 파일이나 화면에 쓰이는 이미지(아이콘 등) 리소스들을 C++ 프로그램이 읽을 수 있게 묶어주는 파일입니다.


* **`HmiController.hpp`**
* **역할:** 화면(QML)에 있는 버튼을 눌렀을 때, 백엔드(C++)에서 어떤 동작을 할지 연결해 주는 컨트롤러 로직입니다.



### ⚙️ 4. 서버 인프라 및 자동화 (Nginx & Systemd)

서버를 껐다 켜도 프로그램이 알아서 잘 돌아가도록 설정하는 파일들입니다.

* **`etc/nginx/`**
* **역할:** 80번 포트로 들어오는 외부 요청을 `networkserver`로 넘겨주는 프록시 설정 파일이 들어있습니다. (Cloudflare 터널과 직접 연결되는 부분)


* **`etc/systemd/system/GuideRobot.WebHmi.service`**
* **역할:** 우분투 리눅스에서 이 서버 프로그램을 **백그라운드 서비스로 자동 실행**하게 만들어주는 데몬 설정 파일입니다.



### 📦 5. ROS2 프로젝트 기본 설정 파일

* **`main.cpp`**
* **역할:** 프로그램의 시작점입니다. 여기서 `NetworkServer`, `Nav2Manager`, `HmiController`를 모두 생성하고 ROS2 노드를 실행시킵니다.


* **`CMakeLists.txt` / `package.xml**`
* **역할:** ROS2(`colcon build`)로 이 프로젝트를 빌드할 때, 어떤 라이브러리(Qt, Nav2 등)를 가져와서 어떻게 컴파일할지 정의한 명세서입니다.


* **`frames_2026-07-30_... .pdf` / `.gv**`
* **역할:** 로봇의 바퀴, 레이저 센서, 맵 등 부품 간의 위치 관계(TF Tree)를 시각적으로 확인하기 위해 뽑아본 디버깅용 파일입니다.
